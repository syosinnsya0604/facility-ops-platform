# A製造株式会社 設備管理システム更改 案件引継ぎ資料

## 1. 案件概要

A製造株式会社では、本社と複数の工場で設備情報を管理している。

現在は工場ごとにExcelを使っており、点検記録や故障・修理記録の管理方法も統一されていない。古い記録については紙で残っているものもある。

現場からは、以下のような話が出ている。

- 「他工場で過去に同じ故障がなかったか探すのが大変」
- 「修理履歴を探すのにかなり時間がかかることがある」
- 「点検予定日を過ぎてから気付いたことがある」
- 「Excelが変更されているけど、誰が変更したのか分からない」

以前、点検記録のExcelファイルを誤って削除したこともあり、一部の記録を入力し直したことがある。

そこで、設備情報・点検記録・故障修理履歴を一つのWebシステムで管理したいという相談を受けている。

システムはAWS上に構築する方向で営業から話が進んでいる。

---

## 2. 利用について

本社と工場からブラウザで利用する予定。

利用者には、以下のような担当者がいる。

- 一般社員
- 点検担当者
- 設備担当者
- システムを管理する担当者

誰でも設備情報を書き換えられる状態にはしたくないとのこと。

利用時間は主に工場が動いている時間帯で、夜間利用は少ない。

顧客からは、

> 「少し止まるくらいなら業務は続けられるが、長時間使えないのは困る」

と言われている。

---

## 3. データ・バックアップ

設備情報、点検記録、故障修理履歴などを扱う予定。

現在のデータは主にExcelで管理されており、一部については紙の記録も存在する。

過去にExcelファイルを誤って削除した経験があるため、顧客はデータを再び失うことをかなり心配している。

そのため、自動的にバックアップできるようにしたいとの要望がある。

---

## 4. セキュリティ・ネットワーク

インターネット経由でAWS上のシステムを利用する予定。

ただし、

> 「データベースをそのままインターネットへ公開するような構成は避けたい」

との要望がある。

また、誰でも設備情報を書き換えられる状態にはしたくない。

---

## 5. 監視・障害対応

システムに問題が発生した場合、担当者が常に監視画面を見続けなくても異常に気付けるようにしたい。

具体的な監視対象、通知方法、通知先などについては現時点では決まっていない。

## 6. 開発体制・環境

アプリケーション開発チームは別に存在する。

インフラチームでは、主に以下を担当する予定。

- AWS環境
- ネットワーク
- 監視
- バックアップ

本番環境とは別に、開発チームが変更内容を確認できる環境も必要になりそう。
